# ADR-0013: Admit CBP Border Wait Times (bwt.cbp.gov) as the first live land source

**Status:** Accepted
**Date:** 2026-09-10
**Source:** CHOKEPOINT-PLAN.md §6, §6.1, §15; research/multimodal-source-research.md

## Context

The multimodal extension's land layer needs the CBP border wait times named in
the design note (e.g. El Paso). Two service paths exist:

- **bwt.cbp.gov** (CBP's own service): `GET /api/waittimes` answered
  unauthenticated on 2026-09-10 with all **85 crossings** (30 Canadian, 55
  Mexican), including El Paso's Bridge of the Americas, Paso Del Norte, and
  Ysleta. Per-lane commercial-vehicle / passenger / pedestrian data with
  `delay_minutes`, `lanes_open`, `operational_status`, and lane update
  timestamps. **No API key.**
- **api.trade.gov** (ITA platform): same data behind a free api.data.gov key
  (1,000 requests/hour default, VERIFIED). During research the platform's TLS
  chain failed validation from the research machine, and its SPA endpoints
  redirected to the marketing home — workable but with more moving parts and
  a mandatory key.

The data is facility-level (a wait-time number at a fixed crossing), which
does not fit `TransportObservation`; the model question is resolved in
ADR-0015. US-government data carries the public-domain basis (17 USC §105);
no restrictive data-use terms were found, though the specific endpoint has no
written reuse statement (the site is a JS app without a linked license page).

## Decision

1. **Admit CBP Border Wait Times (bwt.cbp.gov direct endpoint)** as the first
   live land source:
   - Keyless: no registration, satisfying §6.2 with zero credentials.
   - Attribution: "Border wait times: U.S. Customs and Border Protection" in
     the visible attribution control (§15).
   - Raw samples may be archived for fixture-building (public US-gov data);
     the running adapter keeps only a bounded in-memory buffer.
   - Removal plan: fixture fallback; the api.trade.gov + api.data.gov-key
     path is the documented alternate service if the direct endpoint retires.
2. **Wait-time values are OBSERVED facility metrics, not derived metrics.**
   `delay_minutes` is reported by CBP; Chokepoint normalizes and displays it
   with provenance, and derives nothing about it in v1 (a future baseline
   comparison would be a separate, clearly-labeled derived metric).
3. **Freshness semantics must match the real cadence.** Lane updates are
   periodic per port (strings like "At 7:00 am EDT"); hours-stale readings at
   quiet crossings are NORMAL, not failures. The source-health configuration
   must use a generous freshness threshold and the UI must show the lane
   `update_time` verbatim — a healthy-appearing stale label would be a lie
   the other direction.

## Consequences

- The land layer can run keyless today.
- Geographic scope is US land borders only (the measured side); no Mexican or
  Canadian authority data. Profile limitations must say so.
- 85 crossings exist; Phase 1 of the land layer wires ONE (El Paso / BOTA)
  per the design note, with the config pattern ready for more.
- The endpoint publishes no written SLA; the health state machine (built for
  exactly this) treats gaps and stale updates as expected operation.
