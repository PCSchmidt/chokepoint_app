# ADR-0015: Facility-level signals enter as a new FacilityMetric record, not synthetic TransportObservations

**Status:** Accepted
**Date:** 2026-09-10
**Source:** CHOKEPOINT-PLAN.md §3.1–3.3, §5.1, §5.2, §5.5; research/multimodal-source-research.md

## Context

`TransportObservation` models a MOVING entity: position, kinematics,
per-observation source/quality, entity identity. Air/ADS-B fits it naturally.
CBP border wait times — and any future rail crossing signal — are
FACILITY-LEVEL metrics: a wait-time number (plus lanes-open and operational
status) reported at a fixed facility on a periodic cadence. The design note
posed three options and advised against abusing the existing model.

## Options considered

- **(a) New observation subtype inside TransportObservation**: forces null
  position/kinematics on a subset of records; every vessel-shaped consumer
  (tracks, moving_fraction, cohorts, globe points) must then guard against a
  "position-less observation". Pollutes the well-tested entity model.
- **(b) A separate FacilityMetric record alongside TransportObservation**:
  the facility is not an entity in motion; modeling it honestly is a small,
  clean contract of its own.
- **(c) Synthetic entities abusing the existing model** (e.g. one phantom
  "vehicle" per crossing whose speed encodes the wait): corrupts every
  entity-keyed metric and the truth-state story. Rejected outright.

## Decision

Adopt **(b): a separate `FacilityMetric` record** (a new model in
`src/data/` alongside `observation.ts`), shaped as:

```
FacilityMetric {
  facilityId: string          // stable, provider-scoped (e.g. cbp:070801:BOTA)
  facilityType: "border-crossing" | "rail-crossing" | ...
  displayName: string
  mode: "land" | "rail" | ...
  location: { latitude, longitude } | null   // facility coordinates, OBSERVED metadata
  observedAt: string          // CBP's own reading timestamp
  receivedAt: string          // when Chokepoint ingested it
  measurements: { laneGroup, metric, value, unit }[]  // e.g. commercial|delay_minutes|10|min
  lanesOpen / operationalStatus / update_time (verbatim)
  source / quality blocks: SAME contracts as TransportObservation
  truthState: "OBSERVED"      // CBP-reported; never mixed into vessel counts
}
```

Contract rules, preserving §3.1–3.3 exactly:

1. FacilityMetrics carry their own provenance records and health state, like
   every source adapter's output (§5.1). They never mix into
   `TransportObservation` totals, cohorts, or geofence counts.
2. `delay_minutes` is an **OBSERVED** value (reported by CBP), not a §5.5
   DerivedMetric. Any baseline comparison over it is a separately-versioned
   DERIVED comparison, as with vessel-count baselines (§8.4 COMPARISON).
3. Reject/dedupe/validate at ingestion with the same discipline as AIS
   normalization: non-numeric delays, unknown statuses, and impossible lanes
   values are rejected with reasons, never clamped; missing is UNKNOWN.
4. The manager's snapshot gains a `facilityMetrics` section; the HUD, agent
   tools, and evaluator treat facility claims as a new claim surface
   (OBSERVED facility values with provenance), not as entity claims.

## Consequences

- The air layer reuses `TransportObservation` unchanged; the land layer gets
  an honest home for its shape of data; nothing vessel-shaped is polluted.
- The agent's evaluator needs a FacilityMetric claim type with numeric-accuracy
  checking against the facility map (same rigor, different value map).
- New metrics vocabulary: "border wait time" joins the metric docs as an
  OBSERVED facility metric — defined, versioned, and tested before any UI or
  agent claim uses it.
- Fixture-first testing: CBP's real sample (archived 2026-09-10) seeds a
  SIMULATED fixture for the deterministic suite, exactly as maritime did.
