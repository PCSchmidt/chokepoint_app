# ADR-0012: Admit adsb.lol as the first live air-cargo source; reject OpenSky for live use

**Status:** Accepted
**Date:** 2026-09-10
**Source:** CHOKEPOINT-PLAN.md §6, §6.1, §15; research/multimodal-source-research.md

## Context

The multimodal extension needs an aircraft-position source for the air layer.
DATA_SOURCES.md carried two candidates from Phase 0 (OpenSky Network,
adsb.lol). Research on 2026-09-10 verified their current terms from primary
sources:

- **adsb.lol**: free API (VERIFIED); ODbL v1.0 for the API and all public data
  (VERIFIED in the provider's OpenAPI license field); an API key will be
  required in the future, obtainable by feeding data to the network; live
  probe of `/v2/lat/lon/dist` returned aircraft with position, kinematics,
  type code, registration, and ADS-B quality fields that map onto
  `TransportObservation` exactly as AIS does.
- **OpenSky**: license granted "solely for non-profit research and non-profit
  education", and the terms state that **any operational REST API use —
  including integration into a live product or automated system, even
  internal — requires a previous written agreement, even for non-profits**
  (VERIFIED). Chokepoint's adapter pattern is such an operational use. No
  written agreement is being sought in this phase.

A separate product risk: aircraft do not broadcast a cargo flag. Freight-
operator filtering (FedEx/UPS/Cargolux/Atlas and similar) can only be
inferred from callsign prefixes, registration data, or type codes — the same
"not separable from broadcast data alone" finding as bulk carriers (§2.1).

## Decision

1. **Admit adsb.lol** as the first live air-cargo source, as an explicit,
   documented **risk acceptance** by the project owner (non-commercial
   portfolio demo):
   - ODbL obligations are honored by the ADR-0010 posture: bounded in-memory
     buffer, no raw data committed to the repository, no redistribution of
     raw records; any future published derived database must be ODbL.
   - No production contact is made in this phase (demo scale, no SLA
     expected); if usage grows, contact the operator before scaling.
   - Courtesy attribution ("ADS-B data via adsb.lol (ODbL)") in the visible
     attribution control (§15).
   - Removal plan: fall back to fixture-only for the air layer; no live
     substitute is admitted without a new gate pass.
2. **Reject OpenSky for live adapter use.** The terms barrier is recorded as
   the decision, per the rule that an unfavorable gate result is documented,
   not skipped. A written agreement with OpenSky could reopen this; that is a
   deliberate human step, not an engineering one.
3. **Operator classification is inferred, never asserted.** Freight-operator
   filtering is a display cohort built from provider-published metadata
   (registration/type/airline fields) plus documented callsign-prefix
   heuristics, labeled `classification: "inferred"` with a coverage caveat.
   The agent and evaluator treat claims like "a FedEx flight" as IDENTITY
   claims permitted ONLY on provider-published operator metadata for that
   specific record — never inferred from callsign or type alone.

## Cross-reference: gods-eye-view operational experience

The inspiration repo (PCSchmidt/gods-eye-view) RAN an OpenSky-primary /
adsb.lol-fallback flights layer and documents the operational pattern:
OpenSky needed a fallback in practice; adsb.lol point queries were capped
(~250 nm around the camera subpoint) and explicitly treated as regional
observed context, never worldwide completeness, with per-source provenance
exposed in the UI. Its DATA_SOURCES.md also independently records the same
OpenSky written-agreement caution this ADR is based on. Chokepoint's air
adapter (future phase) inherits those lessons: radius-capped point queries,
regional-completeness caveats, and honest provenance labels.

## Consequences
- When adsb.lol introduces the feeders-only API key, the adapter degrades to
  honest UNAVAILABLE with fixture fallback — the same pattern as the missing
  AISStream key.
- No published rate limits: the adapter must poll conservatively (>= 10 s
  interval, bounded buffer) and treat HTTP 429 as a documented signal to
  back off.
- Aircraft "cargo" classification will carry a visible caveat: coverage is
  limited to freight operators identifiable from published metadata, not a
  complete picture of cargo aviation.
